Help & How It Works

Concepts, limitations, and presentation-ready explanations.

What is fuzz testing?

Traditional testing uses predefined inputs. Fuzz testing generates random, invalid, unexpected and boundary-value inputs to find defects in how an API handles edge cases. This tool automates endpoint configuration, input generation, request execution, response analysis and report generation.

Example

If an API accepts an age field, the engine tests 20, -1, 0, "abc", null to check whether validation works correctly.

What the analyzer flags

  • 5xx responses — server crashes on bad input (Critical/High)
  • Timeouts / connection failures (High)
  • Missing validation — invalid input accepted with 2xx (Medium)
  • Info disclosure — stack traces, SQL errors in response (High)
  • Injection reflection — SQLi / XSS payload echoed back (High)
  • Inconsistent errors — missing error format (Low)
  • Slow responses — performance risk (Medium)

⚠️ Important limitations

  • This tool improves automation & coverage. It does not guarantee detection of every vulnerability — findings must be validated manually.
  • Only test APIs you own or have permission to test.
  • Browser-based testing may hit CORS on some real APIs. Use the Demo API, or run npm run proxy locally (see README). Cloud previews cannot access a proxy running on your own computer.
  • Stateful workflows (RESTler-style dependency chains) are future scope — this version fuzzes single requests deeply.

Keyboard & data

All data is stored in your browser (localStorage). Use Export All Data on the Dashboard to back up endpoints, cases and findings as JSON.
